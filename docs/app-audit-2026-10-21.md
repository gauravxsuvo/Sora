# App audit — 21 October 2026

Sora's backend, device-setting recovery paths, and all ten desktop pages were reviewed. This change adds a saved AMOLED dark theme, improves both fan charts, and fixes the issues below. The application builds with zero warnings and errors.

## Confirmed issues fixed

| Area | Trigger and previous behavior | Result |
| --- | --- | --- |
| General preferences | A settings-file write failed after in-memory preferences had already changed; the error was only logged. The UI appeared saved until restart. | Publish preferences only after the atomic file replacement succeeds. Display a save error and restore the controls on failure. |
| Fan preferences | Structurally invalid JSON, such as a null profile dictionary, raised `InvalidDataException` outside the load error handler. | Reject invalid preferences, keep the source file, and fall back with a logged explanation. |
| GPU fan recovery | Invalid backup/applied-profile structure could escape the load handler. A null backup element also needed explicit rejection. | Handle invalid data; invalid recovery backups block hardware changes and retain an explanation. |
| GPU profile UI | Library/import validation raised `InvalidDataException`, but several UI error handlers did not catch it. | Surface the validation message in the editor rather than letting the exception reach the global handler. |
| Mouse RGB | A static effect marked as applied was never checked again during the same session, although RGB writes use device RAM. USB reconnect or another controller could replace it. | Verify saved static zones every ten seconds through the shared mouse connection; reapply lost state through the existing recovery path. Pause for G HUB and recheck after it exits. Ignore zones currently controlled by reactive lighting. |
| Mouse settings loading | Null saved firmware dictionaries/zone values, null reactive entries, or a missing reactive color could cause null-reference errors. | Reject malformed values and log the problem without crashing startup. |
| Mouse controls | The enabled flag used direct file overwrites, and disabling changed memory before the save completed. | Save through a temporary file and atomic replacement before publishing the enabled flag. A failed disable retains the previous saved choice. |
| Fan chart | Small handles, no keyboard editing, cramped labels, and no indication of the configured native stop interval. | Larger interactive handles, hover/selection readout, arrow-key editing, shaded curve, clearer axes, and nominal stop-region rendering. Point movement preserves temperature ordering, nondecreasing duty, and the final 100% point. |
| GPU chart | The unit property was unused; axes did not distinguish RPM from duty. | Label RPM/duty and temperature explicitly, add plot padding, larger outlined points, and shaded area. |
| Screenshot tooling | An exception during an optional layout check was swallowed by the application's tray-oriented global exception handler, leaving the capture process running. | Write an error report and shut down the screenshot session. |

## Appearance

Dark mode is available under **Settings → Appearance** and is saved in `settings.json`. New and legacy preference files default to dark mode; switching it off retains the light palette. The later Portways Status theme update uses a `#000000` window/sidebar, `#101010` cards, `#0A0A0A` chart insets, and neutral white/gray controls. Purple accents, background gradients, haze, and decorative chart glow have been removed. The native caption and common controls follow the selected palette without restarting. Device artwork retains its physical colors. Current theme evidence is in `artifacts/status-theme`; the earlier audit screenshots record the intermediate design.

The motherboard chart supports dragging, arrow keys, Space to select the next point, and Shift for increments of five. Values remain drafts until Apply. The existing numeric table remains available. Fixed-duty mode uses its slider and does not show curve-editing instructions.

These behaviors were identified and are unchanged by this patch.
